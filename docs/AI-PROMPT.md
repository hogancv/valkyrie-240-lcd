# 让 AI 帮你写副屏程序

这个仓库的定位不是「一个成品软件」，而是**一份能被 AI 读懂的协议 + 一套已经跑通的推流原语**。
把整个仓库丢给 AI（ChatGPT / Claude / Copilot / 本地模型都行），它就能直接写出你要的画面，
**不需要再逆向一次 USB 协议**。

---

## 一、最短用法

复制下面这段，连同仓库一起给 AI：

```text
我有一块瓦尔基里（Myth.Cool）水冷副屏，240×240，USB VID 345F / PID 9132，MS9132 桥接芯片。
我已经有了一份跑通的 Python 实现，就在你看到的这个仓库里：
  - valkyrie_lcd/protocol.py  协议真值（VIC 表、76 条 HID 初始化、帧头帧尾）
  - valkyrie_lcd/panel.py     ValkyriePanel 推流类
  - valkyrie_lcd/color.py     RGB → UYVY 转换
  - docs/PROTOCOL.md          完整协议说明
  - docs/PITFALLS.md          踩过的坑
  - demos/token-board/        一个真实在用的完整例子（数据层 / 画面层 / 调度层）

我要实现的效果是：<在这里写你的需求>

请遵守这些硬约束：
1. 不要修改 protocol.py 里的任何字节/数值，它们是实机验证过的真值。
2. 不要调用 usb.core.Device.reset()，这块屏会被复位搞死（见 PITFALLS.md 第 1 条）。
3. 帧内容用 Pillow 画，尺寸固定 240×240，最后交给 panel.show(img) 或 panel.stream(...)。
4. 只用公开依赖（Pillow / numpy / psutil 等），不要引入 GUI 框架。
5. 代码要能直接 python 运行，并在最后保留 Ctrl+C 优雅退出。

输出：一个完整可运行的 .py 文件 + 运行方式和预期效果说明。
```

## 二、为什么这样分工有效

| 层 | 谁负责 | 说明 |
|---|---|---|
| USB 协议层 | **不要再让 AI 碰** | `protocol.py` / `hid.py` / `color.py` 是已经验证过的常量与字节序，改一个字节就黑屏 |
| 画面层 | **AI 的活** | 用 Pillow 画什么、怎么排版、数据从哪来，全都自由 |
| 调度层 | AI 的活 | 多久刷新一次、异常怎么兜底、要不要常驻 |

一句话：**协议是死的，画面是活的。让 AI 只做活的那部分。**

## 三、可以直接提的需求示例

这些需求都只需要改「画面层」，协议层一行不动：

- 「显示一个每 200ms 更新的 CPU/内存占用环形图，配色跟随占用率从绿到红」
- 「把我指定目录里最新的那张图片轮播，每 10 秒换一张，带淡入淡出」
- 「做一个番茄钟：25 分钟倒计时，期间显示进度环，结束后闪三下」
- 「显示当前网易云/Spotify 正在播放的歌曲名和进度条」
- 「接我自己的 HTTP 接口，把返回的 JSON 里的三个指标画成三行数字」
- 「做一个像素风天气面板，图标用代码画，不要外链图片」
- 「把屏幕当成一个 240×240 的 canvas，跑一个康威生命游戏」

### 先让 AI 抄一份现成的骨架

`demos/token-board/` 是一个**已经在跑的真实实现**，三层拆得很干净：`data.py`（取数）
→ `render.py`（纯渲染）→ `run.py`（节流 + 推流）。要写新面板时，最省事的提法是：

```text
照着 demos/token-board/ 的三层结构写一个新面板，不要发明新架构：
  data.py   换成我的数据源（<CSV / HTTP / 本地文件>）
  render.py 只做 dict -> PIL.Image，不许碰 USB
  run.py    复用它的刷新节流与 Ctrl+C 处理
画面要求：<你的需求>
```

这样 AI 改的只是「填进去什么」，不容易顺手把协议层或推流循环改坏。

## 四、给 AI 的验收清单（可以一起贴给它）

写完代码后，让 AI 自查这几条：

1. 输出尺寸是否严格 240×240（不是 480×480 或 320×240）？
2. 是否只通过 `ValkyriePanel` 接口操作设备，没有直接 `dev.write` 硬编码帧？
3. 异常时是否会掉帧而不崩溃（USB 偶发 timeout 很常见）？
4. 长时间运行会不会内存泄漏（Pillow 图像对象要复用或及时释放）？
5. 是否避免了 12px 以下的中文小字（这块屏看不清）？
6. 是否处理了 Ctrl+C，退出时调用 `panel.close()`？

## 五、如果你要的是「开机自启 + 常驻」

让 AI 在画面层之外再加一层外壳，注意三点：

- 用 `pythonw.exe` 启动（没有黑窗），但**必须先重定向 `sys.stdout`**，
  否则 `print` 会因为 `sys.stdout is None` 直接抛异常（PITFALLS.md 第 9 条）。
- 单实例：监听一个本地端口（例如 `127.0.0.1:47821`）做互斥，
  两个进程同时推流会互相踢掉设备（PITFALLS.md 第 8 条）。
- 掉线重连：设备未枚举时按 2→4→8→30 秒退避重试，别退出。

---

## 六、注意

- AI 生成的代码**不会自动验证画面正确性**。协议层对、画面不对，通常是排版问题；
  画面重复三次/偏色，才是协议参数问题。
- 让 AI 改 `protocol.py` 里的数值之前，先让它读 `docs/PROTOCOL.md` 第六节，
  照着官方日志复核一遍再动手。
