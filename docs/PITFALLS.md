# 踩坑记录

按「踩到的顺序」排，每条都写了**现象 → 原因 → 结论**。
这些坑不是理论推测，是实机反复失败换来的。

---

## 1. ⚠️ 绝对不要对这块屏调 `dev.reset()`

**现象**：设备突然从系统里消失，设备管理器里出现「未知 USB 设备（设备描述符请求失败）」，
硬件 ID 变成 `USB\VID_0000&PID_0005`。拔线、换口、整机断电十分钟，全部无效。

**原因**：MS9132 收到 USB 总线复位后固件会卡死，不再响应任何标准请求。
它不是「重启一下就好」的状态，是彻底挂住。

**救法**（不用拔线）：

```powershell
# 找到报错的父级集线器/设备实例，重启它
pnputil /restart-device "USB\VID_0000&PID_0005\..."
```

重启父级集线器会让总线重新枚举，设备才回来。本仓库 `tools/doctor.py` 也不会碰 reset，
`panel.close()` 里只 `finalize()` 释放用户态句柄。

## 2. 画面横向重复 3 次 + 下半部分空白

**现象**：推上去的图案被横向压缩重复三遍，下面 80 行全黑，颜色也不对。

**原因**：像素格式码填了 `0x11`（RGB888，3 字节/像素）。固件于是按 720 字节/行解析，
实际每行只有 480 字节 → 每 80 个物理像素就重放一次（240/80 = 3），
纵向只填 115200/720 = 160 行。

**结论**：本机面板固定用 **`0x22`（YUV422）**。`0x11` 在别的机型上可能是对的，
但对 240×240 这档是错的。

## 3. 日志「看起来是空的」

**现象**：`%APPDATA%\WinUsbDisplay\*.log` 用 `cat`、`grep`、`Get-Content` 全是空白/乱码。

**原因**：文件是 **UTF-16 LE with BOM**。

**结论**：

```python
text = open(path, "rb").read().decode("utf-16-le", "replace")
```

## 4. 用「写一帧花了多久」判断参数对不对 → 判断不出来

**现象**：参数错的时候，首帧写入依然只要 22 ms，看起来「很成功」。

**原因**：设备只校验字节数，不校验内容语义。只要长度对，它照收不误。

**结论**：唯一可靠的验收方式是**肉眼看屏**。程序返回的 FPS、写入耗时、
"推流中" 状态，都不能证明画面正常。

---

## 5. 设备被官方软件占用

**现象**：`usb.core.find()` 返回 `None`，或者 HID 打开报错。

**原因**：官方 Myth.Cool 常驻时会一直握着 `MI_00` / `MI_03`。

**结论**：推流前确保官方软件已退出（或卸载）。卸载软件**不会**破坏 libusb-win32 驱动，
驱动层是独立的，必须保留。

---

## 6. 把 `MI_03` 的驱动卸了

**现象**：设备在，`libusb0` 后端却找不到它。

**原因**：`MI_03` 靠 `libusb0.sys`（`oem24.inf`）才能被 PyUSB 以 libusb0 后端访问。
用驱动清理工具「顺手清掉」就废了。

**结论**：设备管理器里 `MI_03` 应显示为 `libusb-win32 devices`。
丢了就用 Zadig 重新绑一次（选 libusb-win32，不是 WinUSB）。

---

## 7. 中文字体在副屏上糊成一团

**现象**：240×240 上写 12px 以下的中文，笔画全粘连。

**原因**：物理像素就那么多，24px 见方的字还能看，再小就没救了。

**结论**：这块屏做「大数字 + 极短标签」最合适；
字体用 `msyh.ttc` / `bahnschrift.ttf`，字号不小于 15px。

---

## 8. 两个进程同时推流 → 互相把对方踢死

**现象**：一会儿有一会儿没，或者设备直接失联。

**原因**：同一时刻只允许一个进程持有 bulk 端点。

**结论**：常驻程序里用端口/文件锁做单实例（本仓库的守护方案用
`127.0.0.1:47821` 监听做互斥）。

---

## 9. `pythonw.exe` 下 `print` 直接崩

**现象**：用 `pythonw` 启动后台程序，进程秒退，没有任何输出。

**原因**：`pythonw` 下 `sys.stdout` 是 `None`，`print` 抛 `AttributeError`。

**结论**：后台运行时先把 `sys.stdout/stderr` 重定向到日志文件，再做任何输出。
