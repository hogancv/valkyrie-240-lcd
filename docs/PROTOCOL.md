# 协议说明（240×240 / VID 345F:PID 9132 / MS9132）

> 所有数值都来自**官方驱动自己的日志**，并与两个开源实现交叉核对过：
> `itsmylife44/LcdFusion`（MIT，HID 初始化序列）与 `rhgndf/ms912x`（Linux DRM，帧结构与像素格式）。
> 推测值一律标注了来源，没有标注的就是实测确认过的。

---

## 一、设备拓扑

同一个 USB 复合设备（`VID_345F&PID_9132`，序列号形如 `2019BA****B0`）里有两套完全不同的通道：

| 接口 | 类别 | 用途 | Windows 驱动 |
|---|---|---|---|
| `MI_00` | HID | 控制通道：初始化、几何、帧间保活。9 字节特征报文，走 EP0 | 系统自带 `hidusb`/`hidclass` |
| `MI_01` | Audio | 屏幕自带的小喇叭（与水冷头的音频输出有关） | 系统自带 USB Audio |
| `MI_03` | Vendor | 像素通道：bulk OUT，端点 `0x04` | **`libusb0.sys`（libusb-win32）** |

关键点：**`MI_03` 必须绑 libusb-win32**，不是 WinUSB、也不是 libusb-1.0（rusb）。
`libusb0.dll` 下 `claim_interface(3)` 返回 0，libusb-1.0 下返回 `NOT_SUPPORTED`。
这条最早由 MythCool-Lite issue #1 里 arthurfsy2 的实测指出，与本机现象一致。

所以推流是「HID 发命令 + bulk 灌像素」两条腿，缺一条都不行：

- 只发像素 → 黑屏（面板没被唤醒）
- 只发命令 → 黑屏（没有画面数据）

## 二、控制通道：HID 特征报文

每条命令 8 字节负载，`HidD_SetFeature` 时前面补 1 字节 report id = 0，共 9 字节。
部分命令是「写后读」：写完之后要立刻 `HidD_GetFeature` 读回 9 字节，否则固件状态机不推进。

初始化一共 **76 条**（含 2 条携带几何参数的 `A6` 命令），分四段：

1. **传输模式 / 屏闸**：`A6 03 03` → `B5 C5 58` → `B6 DE EE 01` …
   最后 `B6 F0 04 6D` 对应官方日志的 `addr 0xf004 ← 0x6d`。
2. **面板控制器寄存器 + gamma 加载**：`F5 00 1F {E0,E8,F0,F8}` 四组，
   再 `B5 C0 xx` 从 `0x00` 到 `0x7C` 步进 4 —— 这段是**画面能不能亮的关键**，缺了永远黑屏。
3. **几何 / 使能**：`A6 01` 定像素格式与尺寸，`A6 02` 定 VIC。
4. **收尾**：`A6 04 01 00` 解除 mem freeze，打开视频输出。

完整序列见 `valkyrie_lcd/protocol.py:build_init_sequence()`，逐条带注释。

### 两条几何命令的字节布局

```
A6 01 [W:BE16] [H:BE16] [FMT] 00      240×240 YUV422 → A6 01 00 F0 00 F0 22 00
A6 02 [VIC] 00 [W:BE16] [H:BE16]      240×240 VIC156 → A6 02 9C 00 00 F0 00 F0
```

`FMT` 就是像素格式码，见第四节。

### 运行时寄存器

| 地址 | 值 | 含义 |
|---|---|---|
| `0xF004` | `0x6D` | 传输模式（官方日志 `addr 0xf004, value 0x6d`） |
| `0xF507` | `0x02` / `0x00` | mem freeze 开 / 关 |

对应命令：`B6 F0 04 6D`、`B6 F5 07 02`、`B6 F5 07 00`。

## 三、像素通道：帧结构

每帧 = **8 字节头 + 像素 + 8 字节尾**，240×240 时总长 **115216** 字节
（8 + 240×240×2 + 8）。这个数字可以直接和官方日志的 `start screen for data size 115216` 对上。

### 帧头（取自 ms912x 的 `struct ms912x_frame_update_header`）

```c
struct frame_header {   // 8 字节，紧凑
    __be16 header;      // FF 00
    u8     x;           // 左边界 / 16（必须 16 对齐）
    __be16 y;           // 上边界（像素）
    u8     width;       // 宽度 / 16
    __be16 height;      // 高度（像素，不是 /16！）
};
```

240×240 全屏刷新 → `FF 00 00 00 00 0F 00 F0`
（x=0、y=0、width=240/16=15=0x0F、height=240=0x00F0）

`height` 填像素数这一步很多实现都写错成 `/16`，表现是画面只显示顶上一条。

### 帧尾

固定 8 字节：`FF C0 00 00 00 00 00 00`

### 首帧之后必须补的序列

推完**第一帧**，立刻用 HID 发这四条，否则面板停在 mem freeze，画面不刷新：

```
B5 F5 07          (读)
B6 F5 07 00
A6 05 01 00
B5 C5 55          (读)
```

之后每约 30 帧补一条 `B5 00 32`（读）保活。逻辑在 `panel.py:_post_frame()` / `_commit()`。

## 四、像素格式

`A6 01` 的第 7 字节：

| 值 | 格式 | 字节/像素 | 实际效果 |
|---|---|---|---|
| `0x22` | YUV422 (UYVY) | 2 | **本机面板正确值** |
| `0x11` | RGB888 | 3 | 固件按 720 字节/行解析 → 画面横向重复 3 次、只填 160 行、整体偏色 |

对应 ms912x 驱动的常量：

```c
#define MS912X_PIXFMT_UYVY 0x2200
#define MS912X_PIXFMT_RGB  0x1100
```

UYVY 的字节排列是 `U Y0 V Y1`，水平每两个像素共享一组 U/V。
色彩空间用 BT.601 studio swing（Y ∈ [16,235]），与官方软件一致；
用全范围 0–255 也能出图，但黑不够黑、白会发灰。

转换实现见 `valkyrie_lcd/color.py`，实测 240×240 单帧约 5 ms（numpy 向量化）。

## 五、VIC 表（视频模式码）

取自官方 MSDisplayAddon 日志里的 `MSDevice Config` 静态表。
**VIC 不是分辨率本身**，它是面板固件内部一套时序方案的编号，写错就黑屏或频闪。

| VIC | 面板尺寸 | htotal | vtotal | pixclk | hoff | voff | hsync | vsync |
|---|---|---|---|---|---|---|---|---|
| 143 | 480×480 | 600 | 490 | 1764 | 100 | 8 | 50 | 4 |
| 147 | 240×320 | 452 | 568 | 1540 | 190 | 260 | 5 | 20 |
| 148 | 320×240 | 568 | 452 | 1540 | 206 | 190 | 20 | 5 |
| **156** | **240×240** | **640** | **352** | **1350** | **190** | **51** | **10** | **10** |
| 159 | 480×272 | 600 | 375 | 1350 | 100 | 90 | 50 | 5 |
| 160 | 360×960 | 544 | 996 | 3263 | 102 | 33 | 40 | 10 |

> 同一组 VID/PID 会用在多种面板上，**分辨率和 VIC 必须按具体机型取**，
> 不能按 VID/PID 一套参数通吃。

## 六、怎么自己复核这些值

官方软件（Myth.Cool / WinUsbDisplay 驱动）会写详细日志：

```
%APPDATA%\WinUsbDisplay\winusbdisplay YYYY-MM-DD HH.MM.SS.log
```

**编码是 UTF-16 LE**，直接 `cat`/`grep` 会是空结果，必须按 UTF-16 解码。

里面能直接读到本机的真值：

```
[usb] set_video_in: 240x240, color=0x22, colSel=0x0      ← 像素格式
[usb] set_video_out: vic=156, color=0x0, 240x240         ← VIC
start screen for data size 115216                        ← 整帧字节数
addr 0xf004, value 0x6d                                  ← 运行时寄存器
```

> 注意区分另一个日志目录：
> `%LOCALAPPDATA%\MythCool\OtherLogs\MythCool.exe_MSDisplayAddon.node_<pid>.log`
> 那只是 addon 的启动摘要（几 KB），只有静态配置表，**不给实际下发的 VIC**。

## 七、没验证过的地方

- `480×272`、`480×480`、`240×320`、`360×960` 四档的 VIC 来自官方静态表，
  **本仓库只实机验证了 240×240（VIC 156）**。其余档位代码支持，但没屏可测。
- 帧头里的 `x` / `y` 偏移只验证过 0,0（全屏刷新）。局部刷新理论上可用，未测。
- `COMMIT_EVERY = 30` 是经验值（官方约 38 帧一次），实测 30 稳定，未做极限测试。
